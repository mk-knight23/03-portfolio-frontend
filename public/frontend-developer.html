How I work

  • Understand. I start with the real problem, users and constraints — not a feature list. A short discovery avoids building the wrong thing.
  • Plan. A clear plan: scope, non-goals, the approach, and how we'll verify it works. You always know what's being built and why.
  • Build. Small, tested, verifiable increments. Working software early and often, with clean, maintainable code that follows the project's conventions.
  • Ship & verify. Real deployment, real testing, honest reporting. I verify behavior end-to-end before calling anything done — no 'it should work'.

Frequently asked questions

What frontend stack do you use?

React, Next.js and TypeScript with Tailwind CSS, plus Framer Motion or GSAP for animation and Vitest/Playwright for testing.

Do you do UI/UX design too?

Yes — I work as a design engineer, handling both interface design and production frontend code, so the result matches the vision.

Can you improve an existing site's performance?

Yes. I optimize Core Web Vitals, bundle size, rendering, hydration and accessibility on existing React/Next.js apps.

Do you build design systems?

Yes — reusable component libraries, tokens and documentation so a product stays consistent as it grows.

Are you available for freelance / remote work?

Yes, I take remote frontend contracts and product work. Use the contact page to reach out.

How do you handle animation without hurting performance?

GPU-friendly transforms, reduced-motion support, and 60fps interactions — animation that enhances usability rather than fighting it.
